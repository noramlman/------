# 02 · 工程结构与分层约定

## 一、三层结构（这是全队必须统一的认知）

```
┌──────────────────────────────────────────────────────────┐
│ 应用层（你自己的代码）                                      │
│   Core/Src/app/vision_task.c   ← 视觉：你现在写这里         │
│   Core/Inc/app/                                               │
│         vision_task.h   视觉对外接口                         │
│         app_config.h    总开关（跑哪个任务、ROI、阈值）       │
└───────────────────────┬──────────────────────────────────┘
                        │ 只调用，不修改
┌───────────────────────▼──────────────────────────────────┐
│ 驱动层（实验室提供，稳定，不要动）                            │
│   Core/Src/dcmi_app.c    摄像头采集（DCMI + DMA + 信号量）    │
│   Core/Src/ov2640.c      摄像头寄存器配置（走 I2C2/SCCB）    │
│   Core/Src/lcd_144.c     屏幕驱动（SPI2 + 4 根控制线）       │
│   Core/Src/usb_vcp.c     USB 虚拟串口（打印用）              │
│   Core/Src/cam_lcd.c     原例程的 demo（演示用，可不用）      │
└───────────────────────┬──────────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────────┐
│ 系统层（整合外设时才动）                                     │
│   Core/Src/main.c            各外设 MX_xxx_Init()           │
│   Core/Src/stm32h7xx_it.c    所有中断入口                   │
│   Core/Src/stm32h7xx_hal_msp.c  引脚复用 + DMA + NVIC       │
│   Core/Inc/FreeRTOSConfig.h  堆大小                        │
└──────────────────────────────────────────────────────────┘
```

## 二、每层能做什么、不能做什么

| 层 | 能做 | 绝对不能做 |
|---|---|---|
| **应用层** | 调用驱动函数、写算法、建自己的任务 | 改驱动里的实现、改 `hal_msp.c` 的引脚 |
| **驱动层** | 提供函数给应用层用 | 加业务逻辑、printf 调试输出（除了例程自带的） |
| **系统层** | 加新外设的初始化、合并中断 | 随便改时钟、随便改引脚 |

## 三、你（视觉）的程序入口在哪

`main.c` → `StartDefaultTask()` → 根据 `app_config.h` 里的开关：

```c
#if APP_USE_VISION
  VisionTask(argument);      /* 跑你自己的视觉算法 */
#else
  CamLcdTask(argument);      /* 原例程：只显示摄像头画面，用于验硬件 */
#endif
```

**第一次上板，先把 `APP_USE_VISION` 改成 0**，确认屏幕和摄像头是好的（这是例程原版行为，最可靠）。
确认没问题再改回 1，跑你自己的算法。

## 四、vision_task.c 里的关键位置

```c
for (;;) {
    /* 1. 等一帧 */
    xSemaphoreTake(xRgbFrameSem, ...);

    /* 2. 丢 Cache —— 不能省！ */
    SCB_InvalidateDCache_by_Addr((uint32_t *)rgb_frame, ...);

    /* 3. ★★★ 你的算法 ★★★ */
    Vision_ProcessFrame(rgb_frame, rgb_frame_cnt);

    /* 4. 显示 */

    /* 5. 帧率统计 */

    /* 6. 重启下一帧 —— snapshot 模式必须调 */
    (void)DCMI_RGB_Next();
}
```

### 现在已实现的算法

| 步骤 | 实现 | 对应第一讲 |
|---|---|---|
| RGB565 → 灰度 | `Rgb565_ToGray()` | 第 2 页 |
| 直方图 + Otsu | `Vision_Otsu()` | 第 5 页 |
| 逐行扫描找白色区间 | `Vision_FindEdges()` | 第 14 页 |
| 中线偏差计算 | `Vision_ProcessFrame()` | 第 14 页 |

### 还没实现的（后续步骤）

- 迷宫追边（第 16/17 页）
- 去畸变 / IPM（第 19/20 页）
- 点集平滑 + 等距采样 + 预瞄点（第 22/30 页）
- 转角 + NMS + L/Y 角点（第 23/24/25 页）
- 元素状态机：十字 / 环岛 / 断路（第 31/32 页）
- 数字识别 + 锁存

## 五、已经改过的系统层设置（重要）

| 项目 | 原值 | 新值 | 原因 |
|---|---|---|---|
| `configTOTAL_HEAP_SIZE` | 15360 | **32768** | 加视觉任务后堆不够会创建失败 |
| `defaultTask` 栈 | 4KB | **8KB** | `Vision_Otsu` 里有 `uint32_t hist[256]`（1KB）+ snprintf |

这两处改动在 `FreeRTOSConfig.h` 和 `main.c`，**推仓库时记得跟队友说一声**，否则合并时会冲突。
