# 03 · 整合步骤：把其他例程的驱动加进来

> 现状：本工程 = **例10 的完整驱动** + 你自己的 `vision_task.c`。
> 已经能跑：摄像头采集、屏幕显示、USB 打印。
> 还没加：SD 卡、IMU、PWM、编码器。下面按"加一个是一个"的顺序写。

---

## 零、先记住一条铁律

**所有例程的 `.ioc` 是同一套母板配置（55 引脚完全一致，零冲突）。**
所以加外设时**不要去 CubeMX 里改引脚**，引脚早就配好了，你只需要：
1. 把驱动的 `.c/.h` 拷进来；
2. 把该外设的 `MX_xxx_Init()` 和 `HAL_xxx_MspInit()` 补进系统层；
3. 把中断入口补进 `stm32h7xx_it.c`。

---

## 一、加 SD 卡驱动（优先级最高，专项① 5 分靠它）

### 1.1 要拷的文件

从 `校赛驱动\例11_SD卡存图` 拷：

| 来源 | 目标 |
|---|---|
| `Core/Src/sd_card.c` | `Core/Src/sd_card.c` |
| `Core/Inc/sd_card.h` | `Core/Inc/sd_card.h` |
| `Core/Src/sd_capture.c` | `Core/Src/sd_capture.c`（可选，是应用层示例） |
| `Core/Inc/sd_capture.h` | `Core/Inc/sd_capture.h` |
| `Middlewares/Third_Party/FatFs/` 整个目录 | `Middlewares/Third_Party/FatFs/` |

### 1.2 要改的系统层文件（3 个）

| 文件 | 加什么 | 从哪抄 |
|---|---|---|
| `Core/Src/main.c` | `SD_HandleTypeDef hsd;` + `MX_SDMMC1_SD_Init()` + 调用 | 例11 的 `main.c` |
| `Core/Src/stm32h7xx_hal_msp.c` | `HAL_SD_MspInit()`（PC8~PC12 + PD2 + SDMMC1 时钟 + DMA） | 例11 的 `hal_msp.c` |
| `Core/Src/stm32h7xx_it.c` | `SDMMC1_IRQHandler()`（内部调 `HAL_SD_IRQHandler(&hsd)`） | 例11 的 `it.c` |

### 1.3 要改的编译配置

- **Include 路径**加：`../Middlewares/Third_Party/FatFs/src`、`../Middlewares/Third_Party/FatFs/src/drivers`
- **源文件**加：`sd_card.c`、`ff.c`、`ff_gen_drv.c`、`diskio.c`
- **宏定义**加：`USE_HAL_SD_REGISTER_CALLBACKS=0`（如果例11 里有）

### 1.4 用法（在你的 `vision_task.c` 里）

```c
#include "sd_card.h"

/* 初始化（可以重复调，没插卡会返回 1） */
if (SdCard_Init() == 0) {
    Lcd_ShowString(4, 88, "SD OK", LCD_GREEN, LCD_BLUE);
}

/* 存图：文件名必须是 8.3 大写格式！ */
SdCard_WriteFile("IMG_0001.JPG", buf, len);
```

**注意**：文件名只能 8.3 格式（`IMG_0001.JPG` ✅，`image_20251029_001.jpg` ❌）。
所以"带时间戳"要靠**写一个 log.csv 记录帧号+毫秒数**，而不是靠文件名。

## 二、加 IMU 驱动（MPU6050，控制组要用）

### 2.1 要拷的文件
从 `例5_MPU6050数据读取`：`mpu6050.c/h`、`mpu6050_app.c/h`

### 2.2 已经具备的条件
- **I2C1（PB8/PB9）在 `.ioc` 里已配好**，且**摄像头走 I2C2，两条总线不冲突**
- 但 `main.c` 里**没有 `MX_I2C1_Init()`**，要补：从例5 的 `main.c` 拷 `MX_I2C1_Init()` 和 `hi2c1` 定义
- `hal_msp.c` 里补 `HAL_I2C_MspInit` 的 I2C1 分支（PB8/PB9，AF4，开漏+上拉）
- `it.c` 里补 `I2C1_EV_IRQn` / `I2C1_ER_IRQn` 的 handler（如果用了中断方式）

### 2.3 提醒
**两个 IMU 都在 I2C1 上时，地址不能一样**。MPU6050 默认地址 0x68，通过 AD0 引脚改成 0x69。母板上第二个 IMU 的 AD0 应该已经拉高了，但**要在代码里确认**（例5 的 `mpu6050.c` 里搜地址定义）。

## 三、加 PWM 驱动（4 路，给电机/飞棍风扇）

### 3.1 要拷的文件
从 `例4_四路PWM输出`：`pwm.c/h`

### 3.2 要补的系统层
- `main.c`：`TIM_HandleTypeDef htim2;` + `MX_TIM2_Init()`
- `hal_msp.c`：TIM2 只需要开时钟（PA0~PA3 的引脚配置在 `MX_GPIO_Init` 或 `HAL_TIM_PWM_MspInit` 里，**从例4 原样抄**）
- 无中断（PWM 输出不需要）

### 3.3 引脚
PA0~PA3 = TIM2_CH1~CH4。**注意 PA0/PA1 大概率是电机，PA2/PA3 和飞棍风扇的对应关系要问硬件组**。

---

## 四、加编码器驱动（2 路）

### 4.1 要拷的文件
从 `例2_编码器读取`：`encoder.c/h`

### 4.2 要补的系统层
- `main.c`：`htim1`、`htim4` + `MX_TIM1_Init()`、`MX_TIM4_Init()`
- `hal_msp.c`：`HAL_TIM_Encoder_MspInit()`（TIM1: PE9/PE11 AF1；TIM4: PD12/PD13 AF2）
- 无中断（编码器是硬件计数，读 CNT 寄存器）

### 4.3 引脚
PE9/PE11 = TIM1（编码器 1）；PD12/PD13 = TIM4（编码器 2）

## 五、整合时的 5 个坑（按踩坑概率排序）

| # | 坑 | 后果 | 怎么避 |
|---|---|---|---|
| 1 | **`stm32h7xx_it.c` 直接覆盖** | 某个外设中断不进，比如 SD 卡永远超时 | 逐个函数**追加**，不要整文件替换 |
| 2 | **`hal_msp.c` 直接覆盖** | 摄像头或屏幕引脚被改掉，画面全黑 | 只**追加**新的 `HAL_xxx_MspInit`，不动已有的 |
| 3 | **FreeRTOS 堆不够** | `osThreadNew` 返回 NULL，任务不跑 | 已从 15360 调到 32768；再加任务继续调大 |
| 4 | **文件名不是 8.3 格式** | FatFS 打开失败 | 用 `IMG_0001.JPG` 这种 |
| 5 | **两个例程的 `dcmi_app.c` 版本不同** | 摄像头行为诡异 | 一律用**例10 的**，别的例程只参考应用层 |

## 六、推荐的整合顺序（每步都要能编译+上板验证）

```
第0步  本工程原样编译            → 屏幕出画面（APP_USE_VISION=0）
第1步  切到 APP_USE_VISION=1     → 屏上出 fps/off/th，USB 出日志
第2步  加 SD 卡                  → 能写一个 IMG_0001.JPG 并能读出
第3步  加 PWM                    → 示波器或电机能看到占空比变化
第4步  加编码器                  → 转轮子时计数值变化
第5步  加 IMU                    → 读到角速度/加速度
```

**每一步做完都要 commit 一次**，出问题能回滚。

## 七、CubeMX 到底要不要重新生成？

**两个选择，看你想不想冒险：**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 手动补（推荐）** | 按上面 1.2/2.2/3.2/4.2 从对应例程**拷函数** | 完全可控，不动现有代码 | 要手工合并 3 个文件 |
| **B. CubeMX 重新生成** | 打开 `cam_lcd_demo.ioc` → Generate Code | 一步到位，所有 `MX_xxx_Init` 自动出现 | **会覆盖 `hal_msp.c` 和 `it.c`**，例10 里手写的注释和定制代码会丢 |

> 如果用 B，**生成前先把 `Core/Src/` 整个目录备份一份**，生成后对比差异。
> `main.c` 的 USER CODE 段是安全的（CubeMX 不会动），但 `hal_msp.c` 和 `it.c` 没有 USER CODE 保护。

**我的建议：先走 A。** 三个文件而已，比恢复被覆盖的代码快。
